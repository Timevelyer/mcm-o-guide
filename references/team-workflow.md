# 团队工作流程指南（4 天赛制）

## 📅 时间分配总览

| 时间 | 阶段 | 核心任务 | 负责人 |
|---|---|---|---|
| Day 1 上午 | 题目分析 | 选题、拆解、规划 | 全员 |
| Day 1 下午 | 模型设计 | 确定模型、分工 | 建模手主导 |
| Day 2 | 模型实现 | 编程、数据、初步结果 | 编程手主导 |
| Day 3 | 论文写作 | Introduction、模型、结果 | 论文手主导 |
| Day 4 上午 | 验证分析 | 灵敏度、优劣势、结论 | 全员 |
| Day 4 下午 | 打磨提交 | 一致性检查、格式、提交 | 全员 |

---

## Day 1: 题目分析与模型设计

### 上午（3–4 小时）：全员协作

**08:00–10:00 选题与题目拆解**
- 全员阅读 6 道题，投票选择
- 确定题目后，逐句阅读 6 个子任务
- 提取关键词，识别建模方向

**10:00–12:00 文献调研与初步方案**
- 每人搜索 3–5 篇相关论文
- 整理现有方法，识别创新空间
- 初步确定模型框架

### 下午（4–5 小时）：建模手主导

**13:00–15:00 模型详细设计**
- 建模手：设计核心模型，确定创新点
- 编程手：评估实现难度，准备数据
- 论文手：搭建论文框架（目录、页预算）

**15:00–18:00 任务分解与分工**
- 将 6 个子任务分配给 3 人
- 确定模型间的依赖关系
- 制定时间表和里程碑

**Day 1 交付物：**
- [ ] 题目选择确认
- [ ] 6 个子任务拆解清单
- [ ] 模型框架图
- [ ] 页预算表
- [ ] 分工表

---

## Day 2: 模型实现与初步结果

### 全天（8–10 小时）：编程手主导

**08:00–12:00 核心模型实现**
- 编程手：实现 Task 1 模型，跑出初步结果
- 建模手：完善模型细节，准备 Task 2–3
- 论文手：写 Introduction（背景、复述、文献综述）

**12:00–13:00 午餐 + 进度检查**
- 检查 Task 1 结果是否合理
- 调整模型参数（如需要）

**13:00–18:00 扩展模型实现**
- 编程手：实现 Task 2–3 模型，对比实验
- 建模手：设计 Task 4–6 方案
- 论文手：写 Assumptions + Notations + 模型描述

**18:00–20:00 结果整理与可视化**
- 编程手：生成关键图表（至少 10 张）
- 建模手：分析结果，准备结论
- 论文手：写 Task 1–3 的结果部分

**Day 2 交付物：**
- [ ] Task 1 模型代码 + 结果
- [ ] Task 2–3 模型代码 + 结果
- [ ] 至少 10 张图表
- [ ] Introduction 完成
- [ ] Assumptions + Notations 完成

---

## Day 3: 论文写作与结果完善

### 全天（10–12 小时）：论文手主导

**08:00–12:00 核心章节写作**
- 论文手：写 Task 1–3 的结果与讨论
- 编程手：实现 Task 4–6 模型
- 建模手：审核结果解释，补充理论支撑

**12:00–13:00 午餐 + 进度检查**
- 检查 Task 4–6 结果是否合理
- 调整论文结构（如需要）

**13:00–18:00 完善结果与写作**
- 编程手：完成 Task 4–6，生成图表
- 论文手：写 Task 4–6 的结果与讨论
- 建模手：准备灵敏度分析方案

**18:00–20:00 整合与审校**
- 全员：整合所有结果，确保逻辑连贯
- 论文手：写 Strengths + Weaknesses
- 建模手：写 Conclusion

**Day 3 交付物：**
- [ ] Task 4–6 模型代码 + 结果
- [ ] 所有图表完成（20+ 张）
- [ ] 核心章节完成（Task 1–6）
- [ ] Strengths + Weaknesses 完成
- [ ] Conclusion 完成

---

## Day 4: 验证、打磨与提交

### 上午（4–5 小时）：全员协作

**08:00–10:00 灵敏度分析**
- 编程手：运行灵敏度分析（3 参数 × 3 值）
- 建模手：分析结果，解释敏感性
- 论文手：写 Sensitivity Analysis 章节

**10:00–12:00 摘要写作**
- 论文手：写 Summary（用模板填空）
- 建模手：审核技术细节
- 编程手：审核数字准确性

**12:00–13:00 午餐 + 最终检查**
- 检查摘要是否包含所有 task 的结论
- 检查数字是否与正文一致

### 下午（4–5 小时）：全员协作

**13:00–15:00 一致性检查**
- 全员：逐项检查 checklist.md 中的清单
- 重点检查：摘要数字、假设引用、图表引用

**15:00–16:00 格式与排版**
- 论文手：调整页眉、页码、参考文献格式
- 编程手：检查图表编号、分辨率
- 建模手：检查页数（必须 ≤ 25）

**16:00–17:00 最终审校**
- 全员：快速通读全文，标记明显错误
- 论文手：修正错误
- 编程手：生成最终 PDF

**17:00–18:00 提交**
- 检查文件名、邮件主题、收件人
- 发送邮件
- 确认接收（24–48 小时后）

**Day 4 交付物：**
- [ ] Sensitivity Analysis 完成
- [ ] Summary 完成
- [ ] 一致性检查通过
- [ ] 格式合规
- [ ] PDF 生成
- [ ] 邮件发送

## 🔄 协作流程

### 每日站会（15 分钟）

**时间：** 每天 08:00 和 18:00

**内容：**
1. 昨天完成了什么？
2. 今天计划完成什么？
3. 遇到什么困难？

**输出：** 更新任务清单，调整计划

### 版本控制

**代码：**
- 使用 Git 或云盘同步
- 每次重大修改后提交
- 命名规范：`model_v1.py`, `model_v2.py`

**论文：**
- 使用云文档（Google Docs / 腾讯文档）
- 每天保存一个版本：`paper_day1.docx`, `paper_day2.docx`
- 最终版本：`paper_final.pdf`

**图表：**
- 统一命名：`fig01_background.png`, `fig02_results.png`
- 保存在 `figures/` 文件夹

## ⚠️ 常见协作问题与应对

### 问题 1：进度滞后

**症状：** Day 2 结束时，Task 1 还没完成

**应对：**
- 简化模型（用线性代替非线性）
- 减少对比实验（只对比 2 种方案）
- 优先完成核心任务

### 问题 2：意见分歧

**症状：** 建模手和编程手对模型选择有分歧

**应对：**
- 快速实现两个版本（各 1 小时）
- 对比结果，选择更好的
- 不要争论超过 30 分钟

### 问题 3：沟通不畅

**症状：** 论文手不知道编程手在做什么

**应对：**
- 每日站会必须开
- 使用共享任务清单（Trello / Notion）
- 及时更新进度

---

## 🎯 成功关键

1. **提前规划**：Day 1 下午必须确定模型和分工
2. **快速迭代**：不要追求完美，先完成再优化
3. **频繁沟通**：每日站会 + 共享任务清单
4. **版本控制**：每天保存一个版本，避免丢失
5. **提前提交**：Day 4 下午 17:00 前提交，留 1 小时缓冲

---

**记住：4 天时间很短，完成比完美更重要！**

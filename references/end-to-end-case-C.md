# 端到端案例：C 题（数据洞察）2021 大黄蜂入侵

## 0 案例概述

**题目：** 2021 MCM Problem C — "Asian Giant Hornet (AGH) Invasion"

**核心问题：** 如何利用公众目击数据追踪并消灭入侵的亚洲大黄蜂？

**6 个子任务：**
1. 建立模型预测大黄蜂在华盛顿州的扩散
2. 建立"误判报告"识别系统
3. 建立优先级策略，按"真实可能性"排序报告
4. 提供定期更新模型的方法
5. 提出消灭判定标准
6. 写 Memo 给农业部门

**最终成果：** 25 页论文，17 图，16 表，参考文献 8 篇

---

## 1 题目拆解

| 子任务 | 输入 | 输出 | 建模方向 |
|---|---|---|---|
| 1 | 首次发现位置 + 4389 条目击报告 | 未来分布预测 | 空间仿真 |
| 2 | 报告（文字 + 图片） | 误判 vs 真实 | 图像分类 + NLP |
| 3 | 报告 + 概率估计 | 优先级排序 | 贝叶斯推断 |
| 4 | 新报告（增量） | 更新后的分布 | 在线学习 |
| 5 | 模型输出 + 时间 | 是否消灭 | 统计判定 |
| 6 | 全部结论 | Memo | 政策建议 |

**关键识别：** 这是一个**多模态融合**题目（空间数据 + 图像 + 文字 + 时序）。
单一模型无法覆盖全部任务，必须设计模型链。

---

## 2 模型链设计

```
数据预处理 → CA 扩散模型 → 概率分布 P(AGH|区域,t)
                              ↓
图像分类（VGG-11 + SVM）→ P(真报|图片)
                              ↓
朴素贝叶斯推断 → P(真实目击|报告)
                              ↓
优先级排序策略
                              ↓
Baum-Welch 在线更新 → 更新后的 CA 分布
                              ↓
消灭判定（连续无阳性报告）
```

**4 个模型 + 2 个辅助系统**，覆盖全部 6 个子任务。

### 模型 1：元胞自动机（CA）扩散模型

**核心创新：** 将大黄蜂季节性行为嵌入 CA 更新规则

| 元素 | 设计 |
|---|---|
| 网格 | 45×65 = 2925 个 12km×12km 单元 |
| 邻域 | Moore 邻域（8 邻居） |
| 更新规则 | 夏季：繁殖 + 扩散；冬季：衰亡 + 静止 |
| 适居指数 | S = -log(P) + B（人口 + 地理障碍） |
| 转移概率 | T = softmax(S_adj) × a（softmax 归一化） |

**为什么这样设计：**
- CA 适合空间离散扩散（Markov 性质）
- 季节性规则符合大黄蜂生物学
- softmax 转移概率自然归一化，避免手工调权

### 模型 2：图像分类

**核心设计：** 两阶段分类（预训练 VGG-11 → SVM）

| 元素 | 设计 |
|---|---|
| 基础架构 | 预训练 VGG-11（迁移学习） |
| 分类器 | SVM（处理小样本 + 不平衡） |
| 数据增强 | 旋转 + 裁剪 + 高斯模糊（扩充阳性样本） |
| 划分 | 训练 2019-09-19 至 2020-05-15；测试 2020-05-15 后 |
| 指标 | 准确率 90.2%，AUROC 94.4% |

**为什么 VGG+SVM 而非端到端微调：**
- 阳性样本仅 14 条（0.3%），端到端训练会过拟合
- VGG 提取通用视觉特征，SVM 在小样本下更稳健
- 数据增强扩充阳性样本，缓解不平衡

### 模型 3：朴素贝叶斯推断

**核心设计：** 多源概率融合

```
P(真实目击|报告) = P(AGH|区域,t) × P(报告频率|区域,t) × P(真报|图片)
```

三个因子分别来自 CA 模型、报告统计、图像分类。
朴素贝叶斯假设三者独立，便于组合多模态证据。

### 模型 4：Baum-Welch 在线更新

**核心创新：** 借鉴 HMM 参数学习，实现 CA 的在线更新

```
新报告到达 → Monte Carlo 采样后验 → 更新 CA 参数 → 重跑扩散
```

**为什么这样设计：**
- 静态模型无法适应新数据
- Baum-Welch 是 HMM 参数学习的经典方法，移植到 CA 是创新组合
- Monte Carlo 采样避免解析后验不可行的问题

---

## 3 数据驱动创新（本题最大亮点）

### 3.1 关键观察

> 4389 条目击报告，仅 14 条阳性（0.3%）

### 3.2 反直觉推断

> 既然 99.7% 是误报，那报告频率反映的不是大黄蜂分布，而是**人口分布**。

### 3.3 模型创新

用误报数据反推人口分布：
```
P(x,y) = Σ_r 1/(√(2π)σ) × exp(-((x-rx)²+(y-ry)²)/(2σ²))
```
其中 r 是报告位置，σ 是可调参数。

### 3.4 验证

将拟合的人口分布与实际城市位置对比：
- ✅ 成功定位 Vancouver、Seattle、Portland（西海岸三大城市）
- ✅ 成功识别 Spokane、Kennewick（东部、南部城市）
- ✅ 中南部空白区对应 Yakama 印第安保留地（人口稀少）

**这就是"数据驱动创新"——不是被动使用数据，而是从数据中发现非显然的模式。**

## 4 灵敏度分析

### 4.1 方法：初始条件扰动 + KL 散度

```
9 组不同初始分布 → 各自跑 CA → 在 t=300,600,1800,3600 比较输出分布
→ 计算 KL 散度 → 构造 95% 置信区间
```

### 4.2 结论

> "Result shows that our model is robust against disturbance, and the 95% confident interval tends to become even smaller as the evolution continues."

### 4.3 为什么这个灵敏度分析高于平均

| 普通做法 | 本文做法 |
|---|---|
| 扫 1-2 个参数 ±10% | 扰动初始分布（9 组） |
| 只看均值变化 | 用 KL 散度量化分布差异 |
| 给一个表格 | 构造 95% 置信区间 + 可视化 |
| 结论："模型稳定" | 结论："置信区间随时间缩小"（有理论支撑） |

## 6 从这篇论文学到的

### 6.1 成功要素

1. **多模态融合**：CA + 图像分类 + 贝叶斯，不是单一模型硬撑
2. **数据驱动创新**：从 0.3% 阳性率反推人口分布
3. **数字密度极高**：摘要 9+ 个具体数字
4. **高级灵敏度分析**：KL 散度 + 95% 置信区间
5. **在线更新机制**：Baum-Welch 让模型适应新数据
6. **方法命名**：CA、Naive Bayes、Baum-Welch——评委好记

### 6.2 可改进

1. 摘要较长（可能超 1 页），需压缩
2. 灵敏度部分无"模型对 X 敏感"的具体结论句
3. 部分图表（KL 散度热力图）解读不够详细

### 6.3 可迁移战术

1. **从数据反常观察驱动创新**：99.7% 误报 → 人口分布模型
2. **小样本用迁移学习 + SVM**：而非端到端训练
3. **多模态概率融合**：朴素贝叶斯组合多源证据
4. **在线更新**：让静态模型变成动态自适应
5. **高级灵敏度**：KL 散度 + 置信区间 > 简单参数扫描

## 7 如果你来做这道题

### 7.1 你会怎么做？

| Task | 推荐方法 | 创新点 |
|---|---|---|
| 1 | CA 或 SEIR 变体 | 季节性规则 + 适居指数 |
| 2 | 预训练 CNN + SVM | 迁移学习 + 数据增强 |
| 3 | 贝叶斯推断 | 多源概率融合 |
| 4 | 在线学习 | Baum-Welch 或粒子滤波 |
| 5 | 统计判定 | 连续无阳性 N 天 |
| 6 | Memo | 从模型结果推建议 |

### 7.2 你能超过这篇吗？

**可能：**
- 用真实气候数据替代假设参数
- 用更先进的扩散模型（如反应扩散方程）
- 增加经济成本分析（消灭 vs 忽视的成本）

**困难：**
- 25 页限制，多模态模型难以全部展开
- 数据极度不平衡（0.3% 阳性），分类难度大
- 在线更新机制实现复杂

**结论：** 这篇是高质量 O 奖，超越需要更大数据集或更深度方法。

---

## 8 总结

这个案例展示了 **C 题（数据洞察）** 的核心打法：

1. **多模态融合是关键**：单一模型无法覆盖"预测 + 识别 + 排序 + 更新"
2. **数据驱动创新最加分**：从数据中发现非显然模式（误报→人口）
3. **数字密度决定摘要质量**：9+ 个具体数字远超平均
4. **高级灵敏度分析拉开差距**：KL 散度 + 置信区间 > 参数扫描
5. **在线更新机制体现工程思维**：让模型适应新数据

**关键教训：** C 题不是"用最好的算法"，而是"最巧妙地利用数据"。
